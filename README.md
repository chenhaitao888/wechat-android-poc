# 安卓微信群 @ 固定回复 PoC

本项目验证《渠道微信群 AI 机器人方案.md》中的安卓真机路径。手机端范围仍为测试群 `测试1`、机器人群昵称 `jarvis` 和固定测试回复。2026-10-26新增独立的 [Mac智能体后端联调](backend/README.md)：模拟订单查询、草稿审核和发件箱已打通，尚未连接手机收发，也未接真实业务或知识库。

## 获取与本地配置

代码仓库：`chenhaitao888/wechat-android-poc`。开发环境为 macOS、Python 3、Node.js（语法检查）、JDK 和 Android adb。固定回执机器人运行时只需要安卓手机，Mac 用于开发和部署。新增智能体后端首轮运行在本 Mac，进行智能体联调时需保持 Mac 运行。

克隆后将 `device.example.json` 复制为本地 `device.json`，填写 `adb devices -l` 显示的设备编号。本文命令里的 `YOUR_DEVICE_SERIAL` 需要替换为该编号。该文件是联调说明，脚本实际目标群仍固定为 `测试1`。

仓库只保存代码、配置示例和验证结论。`artifacts/` 原始聊天/诊断记录、`checkpoints/` 本机回退副本、`vendor/` 安装包和 SDK、设备编号、APK 以及 `.signing/` 私钥不上传。下文对这些路径的引用是本地联调留档，并非仓库随附文件。

## 当前结论

截至2026-10-23，已在华为 DCO-AL00（HarmonyOS 4.2.0 / Android 兼容版本 12）、微信 8.0.79、AutoX.js 7.2.4 mini 上打通：

`记录已读消息边界 → 微信会话列表出现 [有人@我] → 进入测试1核对整批未读 → 唯一可归属时发送固定回复 → 返回列表`

这台手机上，单独开启 AutoX 无障碍服务时，微信只暴露空的根节点；开启华为系统“屏幕朗读”后，聊天内容和输入框可读、可操作。前两轮成功结果依赖这个条件。第三阶段新建了“微信控件辅助”：系统屏幕朗读关闭时，已恢复微信控件读取（574 个节点），手指单击与无朗读声由用户确认；测试008自动回复、拔线后的测试009自动回复均已收到。第五阶段完成新辅助模式的完整30分钟拔线运行：017/018均收到，到时自动停止，无重复发送。第六阶段修复辅助服务与页面恢复逻辑；第七阶段用这一版本再次完成30分钟拔线运行，断网期间发送的025在恢复联网后收到，024/026也收到，三条各回复一次并自动到时停止。第八阶段补充了 AutoX 强制退出和手机重启后的人工恢复：历史编号保留，重复027/028不再回复，新编号028/029正常回复；同时修复服务变化后普通单击失效的问题。第九阶段复测发现拔线后进程出现长时间停顿；调整 AutoX 后台活动和电池优化设置后，当时版本完成30分钟拔线复测，034/035各回复一次并由接收端确认，到时自动停止。第十阶段发现控件辅助曾被华为夜间清理强制停止；为辅助应用补齐后台设置后，两项应用的后台设置和辅助服务均经重启保留，拔线启动后的036正常回复。跨夜是否仍会清理尚待观察。随后面板补齐两项应用的电池优化启动检查和设置入口，新增辅助应用健康记录，037短测回复收到。第十二阶段将触发内容扩展到普通问题：同一句话分别发送可获得不同回执，粘贴 @ 和无 @ 的文字不触发，正常停止后重新启动的拔线短测也通过；本次普通问题版本尚未完成30分钟或跨夜验证。机器人在手机上运行，不需要一直连接 Mac。只说明这组设备与版本的实验结果，尚不能证明不同机型、多群或全天运行可用。

## 触发条件和边界

- 只查找当前可见且唯一的 `测试1` 会话，不遍历其他群。
- 会话摘要必须以微信显示的 `[有人@我]` 开头，未读数为 `1–5`。整批必须是完整可见的收到的纯文字，且只出现一个 @ 符号。支持从成员列表选择 `@jarvis` 后输入非空普通问题，或继续使用 `@jarvis 测试NNN`（三位编号）。普通问题需以该 @ 开头，昵称与正文之间保留微信插入的空白。
- 启动时只在未读为0的测试群记录已读边界；进入群后的新增消息数必须等于未读数，最后一条必须与会话摘要一致。边界找不到、重复或内容变化就暂停。
- 进入群后再次核对标题、消息正文和方向；输入框非空就停止，不覆盖人工草稿。
- 启动最多等待20秒让屏幕、辅助服务和测试群列表就绪；进入群及返回列表各最多等待8秒，超时停止，不重复点击导航。
- 运行中熄屏、锁屏或控件辅助关闭时进入等待状态，不操作微信；保持同一监听轮次，人工恢复条件并返回微信列表后继续核对原未读边界。界面操作过程中条件失效会停止，需要检查后重新开始。
- 发送前将测试编号或普通问题回执写入去重记录。发送结果不确定时停止，不自动重试。相同测试编号不会再次回复。普通问题按已验证的未读边界生成本地回执，分别发送的相同正文可以各获一次确认；本地回执不是微信消息ID，不能保证任意界面中断或人工重放都能准确归属。
- 手机面板每次启动最多 30 分钟、最多 10 条回复；可在手机面板点“停止回复”。脚本在手机上运行，不调用模型或网络接口。旧版命令行默认 10 分钟 / 5 条；若手机已有面板生成的 run-request.json，则按其中的 30 分钟模式运行。
- 多条 @、未读超过5条、摘要截断、消息未完整显示、图片/系统消息、界面被打断等情况会暂停或无法处理。本版不自动恢复复杂界面。普通问题只返回固定确认，不回答问题内容；带额外 @（包括邮箱）、空问题、长消息导致摘要截断或边界不可见时仍会暂停。
- 歧义批次进入群后可能已被微信标为已读；脚本将内容保存到本机 `artifacts/pending-batch.json` 并退出，面板显示原因，需要人工检查，不会自动补发。

`[有人@我]` 是会话级 UI 标记，不是每条消息的结构化 mention 元数据。本版通过“已读边界 + 完整未读批次 + 唯一 @ + 摘要与群内复核”限定验证范围。该方法基于当前设备的 UI 观察，不能替代消息级 mention 元数据，也不能保证高并发、聊天页内新到消息的完整捕获。多条 @ 的精确归属仍未解决。

- `scripts/summarize-run.py`：核验已结束运行的时长、发送次数、USB、辅助服务、前台服务和电池豁免状态；原始聊天记录保留在本机。

- `inspect-test-group.js`：机器人停止时只读检查测试群的摘要、消息节点和 @ 元信息，不操作输入框。

## 在手机上复测（不需要 Mac）

手机桌面已有 **“微信群测试”** 图标。它会打开控制面板，不会立即开始自动回复。

这台华为需先完成运行设置：在 AutoX 左侧菜单开启“前台服务”；在系统“设置 → 应用和服务 → 应用启动管理”中，分别对 **Autox.js v7 和微信控件辅助** 关闭“自动管理”，开启“允许后台活动”并确认；在系统“电池优化 → 所有应用”中，将这两项应用都设置为“不允许”优化。当前测试没有开启自启动或关联启动。可从启动管理右上角菜单进入“批量手动管理”，只查看这两行是否勾选“后台活动”，不要操作“全部”。面板应显示“前台运行：已开启”“AutoX电池优化：已豁免”“控件辅助电池优化：已豁免”。电池优化未豁免或无法确认时，面板不会启动回复；可点“打开电池优化设置”按提示处理。两项“允许后台活动”仍需在系统页面另行核对。仅开启前台服务不足以保证拔线后持续运行。

1. 手机联网、解锁。USB 连接 Mac 不再是复测前提。在系统无障碍设置中开启 AutoX 服务和“微信控件辅助”（当前为 `0.2-test`）。系统屏幕朗读保持关闭。面板里的“打开微信控件辅助”可查看状态、打开设置和关闭辅助服务。原有屏幕朗读方式仍作为回退。
2. 打开微信 `测试1` 群，读掉旧未读，确认输入框为空，再退回聊天列表。
3. 回到桌面，打开“微信群测试”，点 **“开始测试（30分钟）”**。程序会短暂进入测试群记录已读位置，再返回聊天列表；准备完成后再发送新消息，保持 `测试1` 可见。
4. 用另一台手机真正 @jarvis，发送普通问题，例如 `怎么申请？`。收到“收到你的消息（自动回复测试，回执 Q…）。”后再继续；回执号由手机生成，无需自己填写。编号联调仍可使用面板提示的 `测试038` 等新编号。批次联调可在一条真正 @ 后跟一条普通消息；同一批多条 @ 会暂停。
5. 测完回到桌面打开“微信群测试”，点 **“停止回复”**，等面板显示“已停止”。随后可以在“微信控件辅助”中点“关闭辅助服务”。

回退到系统屏幕朗读时，通常需要 **单击选中，再双击激活**。新辅助方式请求触摸直通，以保留普通单击；模拟触摸与用户手指单击均已通过，用户确认没有朗读声。系统屏幕朗读和辅助服务都关闭时，这台手机上的微信控件会变为不可读。

面板会显示当前状态、运行时间、本轮回复数量、下一个测试编号、辅助服务、两项电池优化和系统屏幕朗读状态。查看面板期间不识别微信消息，点击“打开微信 / 返回等待”并回到聊天列表后继续。熄屏/锁屏时显示“等待手机亮屏并解锁”，辅助服务不可用时显示“等待控件辅助恢复”；等待时间仍计入30分钟上限。每轮最多 30 分钟或 10 条回复，达到任一限制后自动结束。

普通问题和 `测试NNN` 都是群消息，不需要修改代码或配置。真正 @ 必须从微信成员列表选择 jarvis，直接粘贴纯文字 @jarvis 不会触发。`测试`加三位数字仍保留为旧编号模式，已处理编号不会重复回复；普通问题在收到回执后再次发送相同内容，会分配新的回执。

### 辅助应用构建与回退

在项目根目录先运行 `python3 scripts/setup-sdk.py` 准备已固定版本的 Google SDK（macOS），然后运行 `python3 accessibility-helper/build.py`，产物为 `accessibility-helper/build/wechat-accessibility-helper.apk`。使用本机 JDK、Google 官方 Android 35 平台与 Build Tools 35.0.0，不依赖 Gradle 或第三方库。签名文件仅用于本地联调，存放在 `accessibility-helper/.signing/`，不要提交或分享。

工具包 SHA-1 已与 Google 仓库元数据核对：`platform-35_r02.zip` 为 `0bb560a90a7a2cbd0dd8348224d518b638fe7949`；`build-tools_r35_macosx.zip` 为 `93ab8ce91230e067b5add4bfa79919c52b27f072`。

历史回退副本用于维护比对。普通文字版本在 `watch-state.json` 中新增 `textReplies` 和 `boundaryVersion`；旧监听启动后会丢弃这些新字段，因此不能直接替换成旧脚本再启动。如需降级，先停止并完整备份手机状态和事件，完成保留新旧回执的迁移后再验证。不要清空或用旧状态覆盖当前 `watch-state.json`。仅切换到系统屏幕朗读时可沿用当前脚本，停止后关闭“微信控件辅助”再开启朗读。
